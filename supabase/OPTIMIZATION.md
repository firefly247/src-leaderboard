# 용량 최적화와 사진 관리

사용자 요청(2026-10-26)에 따라 다음을 적용합니다. 운영 DB를 Supabase로 전환하는 작업은 별도 지시 때만 수행합니다.

## 변경된 행만 저장

`club_store_commit`은 `p_changes`를 받습니다. 테이블별 `upsert`와 기본키로 지정한 `remove`만 전송하며, 수정하지 않은 행은 다시 쓰지 않습니다. 실제 PostgreSQL 테스트에서 수정하지 않은 행의 `ctid`가 유지되는 것을 확인합니다. 여러 테이블의 관련 변경은 같은 트랜잭션과 저장 버전 검사로 보호합니다. 수정 사항이 없으면 저장 버전도 올리지 않습니다.

## 신청 이력의 단일 내용 저장

`club_request_log`의 물리 컬럼은 다음 8개입니다.

`request_id`, `request_type`, `requested_at`, `source_json`, `status`, `processed_at`, `result`, `record_id`

이름·종목·기록·날짜·사진 주소 등은 `source_json` 안에서 보관하고 화면 표시용 컬럼은 서버에서 계산합니다. 원래 요청값과 확정된 표시값이 다른 경우에만 `__club_summary`에 차이값을 보존합니다. 이 내부 차이값은 기존 승인 API의 신청 JSON에 노출하지 않습니다. 구형 스프레드시트 API와 승인 화면의 응답 형태는 유지합니다.

초기 SQL의 17컬럼 테이블이 비어 있을 때만 축소 SQL을 적용하도록 가드를 넣었습니다. 비어 있지 않으면 자동 삭제하지 않고 중단합니다. Google 원본 스프레드시트와 백업 파일에는 이 컬럼 축소를 적용하지 않습니다.

## 사진 150KB와 내용 중복 제거

- 새 업로드의 상한은 클라이언트와 서버 모두 **153,600바이트(150KiB)**입니다. 화면에서는 관례적으로 150KB로 표기합니다.
- 최대 1600픽셀에서 JPEG 품질을 먼저 조절하고, 상한을 넘는 경우에 해상도를 단계적으로 줄입니다. 한도를 충족하지 못하면 업로드를 거부합니다. 한도 자체가 글자 가독성을 보장하지는 않습니다.
- 사용자 후속 지시에 따라 기존 사진도 압축했습니다. 해상도와 URL을 유지하며 더 작아지는 경우에만 압축본으로 교체했습니다. Google 스프레드시트 사본과 사진 폴더 ZIP 백업은 유지합니다.
- 신규 사진이 기존 GitHub 사진과 바이트 단위로 같으면 기존 파일 주소를 재사용합니다. 새 사진 경로는 SHA-256 기반으로 결정합니다.
- 기존 중복 정리 함수 `deduplicateProofFiles`는 같은 Git blob 해시의 사진들을 묶고, CSV와 스프레드시트의 링크를 남길 파일로 변경한 뒤에 중복 파일을 Git 커밋으로 제거합니다. GitHub 브랜치 갱신은 강제 덮어쓰기를 사용하지 않습니다. 원본 파일들은 이전 Git 커밋 및 ZIP 백업에 남습니다.
- Supabase 사진 백업도 내용이 같은 사진을 한 번만 업로드합니다. 원본 경로별 복사 대신 해시 기반 파일명으로 비공개 버킷에 저장합니다.

## 대회 목록과 연도별 개최일

`club_competitions`는 대회 자체의 ID·이름을 한 번 저장합니다. `club_competition_dates`는 `(competition_id, year)`를 키로 연도별 개최일을 저장합니다. 동일 대회의 여러 해 기록을 하나의 대회로 묶으며 대회명 반복 저장을 피하기 위해 이 구분을 유지합니다.
