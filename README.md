# 삼성조정클럽 에르고 · 대회 리더보드

GitHub Pages의 공개 UI, 저장소의 CSV를 최종 승인 기록 저장소, Google Apps Script를 요청·관리 API로 사용하는 에르고 및 조정대회 리더보드입니다.

## 구조

Supabase는 기존 저장소를 유지한 상태로 연결을 준비했습니다. 테이블 생성 SQL과 서버 설정은 [Supabase 연결 준비](supabase/README.md)를 참고하세요. 아직 데이터 이전이나 저장 경로 전환은 하지 않았습니다.

- data/records.csv: 승인된 기록의 최종 저장소입니다. 기존 이름·종목·기록·대회·날짜·메모 구조를 유지하고 정확한 삭제를 위한 record_id를 추가했습니다.
- data/events.csv: event_id, event_name으로 관리되는 동적 종목 목록입니다. 기본값은 500m, 1000m, 2000m입니다.
- data/competitions.csv: 관리자가 추가·수정·삭제하는 조정대회 목록입니다.
- data/competition_dates.csv: 대회 ID·연도별 개최일을 저장합니다. 관리자 → 기준정보 관리 → 대회 개최일에서 출전 기록에 있는 조합의 날짜를 입력·변경·해제합니다. 같은 연도의 대회는 개최일 내림차순으로 정렬하고, 미입력 대회는 해당 연도의 마지막에 표시합니다. 대회명을 변경해도 ID가 같으면 날짜는 유지됩니다. 프런트엔드와 Apps Script를 함께 배포해야 합니다.
- data/competition_events.csv: 4X+, 8+처럼 관리되는 대회 종목 목록입니다.
- data/competition_divisions.csv: 남자·여자·혼성 및 160 체급으로 구성되는 출전 구분 목록입니다.
- data/competition_records.csv: 회원별 대회 참가 연도·종목·출전 구분과 금·은·동메달 수를 저장합니다. 같은 대회의 여러 종목에 출전해도 대회 참석 횟수는 한 번으로 집계합니다.
- apps-script/Code.gs: 비밀번호 인증, 요청 이력, GitHub 저장소 내 증빙사진 저장, GitHub API 커밋을 처리하는 서버 코드입니다.
- GitHub Pages: CSV를 읽어 리더보드, 신청, 관리자 화면을 제공합니다. 민감정보는 포함하지 않습니다.

## Apps Script 배포

카카오 회원 로그인 설정은 [카카오 로그인 안내](docs/kakao-login.md)를 참고하세요. 카카오 앱 키를 등록하기 전까지 로그인 버튼은 준비 중으로 표시됩니다.

1. 새 Apps Script 프로젝트를 만들고 apps-script/Code.gs를 붙여 넣습니다.
2. 비공개 Google Spreadsheet를 하나 만들고 해당 ID를 준비합니다. 이 스프레드시트는 요청·처리 이력 및 관리자 전용 기준정보를 저장하며 공개 기록 저장소가 아닙니다. 증빙사진은 저장소의 data/proofs/ 폴더에 저장됩니다.
3. 프로젝트 설정의 Script Properties에 다음 값을 등록합니다.

| 키 | 값 |
| --- | --- |
| ADMIN_PASSWORD | 관리자 비밀번호 |
| GITHUB_TOKEN | Contents 읽기/쓰기 권한이 있는 GitHub Fine-grained PAT |
| GITHUB_OWNER | 예: firefly247 |
| GITHUB_REPO | 예: src-leaderboard |
| GITHUB_BRANCH | 선택값, 기본 main |
| REQUEST_SHEET_ID | 비공개 이력 Spreadsheet ID |

4. Apps Script를 웹 앱으로 배포합니다. 실행 주체는 배포자, 액세스 권한은 신청자가 API에 접근할 수 있는 범위로 설정합니다.
5. 배포된 /exec URL을 static/leaderboard.js의 API_URL에 넣습니다. 이 URL은 공개되어도 되며, 비밀번호·PAT는 절대 프런트엔드에 넣지 않습니다.
6. GitHub Pages 설정에서 이 저장소의 기본 브랜치를 배포 원본으로 지정합니다.

## 동작 및 보안

- 공개 사용자는 사진을 브라우저에서 JPEG로 자동 리사이즈/압축한 뒤(500KB 이하) 기록을 요청합니다. 사진은 data/proofs/에 커밋되고, 요청은 승인 전 records.csv를 변경하지 않습니다.
- 신규 회원은 첫 기록이 승인되는 시점에 records.csv에 나타나므로 이후 회원 목록에 가나다순으로 자동 표시됩니다.
- 관리자는 단일 비밀번호로 인증하고, 승인 시 Apps Script가 GitHub Contents API로 CSV를 수정하고 commit합니다. 거절은 CSV를 변경하지 않습니다.
- 대회·에르고 기록 요청 화면에는 승인 대기 중인 신규 요청만 표시됩니다. 관리자는 요청을 선택하거나 전체 선택한 뒤 최대 100건까지 한 번에 승인하거나 거절할 수 있습니다.
- 삭제 승인에는 항상 record_id를 사용합니다. 요청 원본, 요청/처리 시각, 상태, 결과, 사유는 이력 시트에서 삭제하지 않고 보관합니다.
- 종목 이름 변경은 event_id를 유지합니다. 연결 기록이 하나라도 있으면 종목 삭제가 거부됩니다.
- 대회 탭은 `대회 출석왕 TOP 5`, `메달 명예의 전당 TOP 5`, 클럽 총 메달, 대회별 메달 매트릭스, 회원별 메달 현황을 제공합니다. 메달 순위는 금메달, 은메달, 동메달 순으로 비교합니다.
- 대회 기록 신청에서 목록에 없는 대회명을 직접 입력할 수 있습니다. 관리자가 승인하면 새 대회와 참가 이력이 함께 생성됩니다.
- 대회 종목도 목록에서 선택하거나 직접 입력할 수 있으며 관리자가 별도 목록으로 관리합니다.
- 대회 이름 변경은 연결된 참가 이력에도 반영됩니다. 연결 기록이 있는 대회는 삭제할 수 없습니다.
- 관리자 → 기록 관리의 **에르고 기록 현황**, **대회 기록 현황**에서 승인된 기록을 이름·대회·종목 및 연도로 검색하고 수정할 수 있습니다. 기록 ID와 증빙사진은 유지됩니다. 대회 수정의 '같은 팀 공통정보 함께 수정'을 선택하면 대회·연도·종목·나이대·대회유형·메달·팀명을 팀 전체에 적용하고, 이름·역할은 선택한 선수만 변경합니다. 조회 이후 변경된 기록은 다시 조회해야 저장할 수 있습니다.
- 증빙사진은 공개 GitHub 저장소의 data/proofs/에 저장됩니다. 따라서 승인 대기·거절 상태의 사진도 URL을 알면 공개적으로 접근할 수 있습니다. 리더보드에서는 승인된 기록 숫자만 사진 팝업 링크가 됩니다.

## 선수 정보 관리

- **관리자 → 기준정보 관리 → 선수 정보**에서 선수별 4자리 출생연도와 가입연도를 조회·저장합니다. 에르고·대회 승인 기록의 회원을 합쳐 가나다순으로 표시하며 이름 검색을 지원합니다.
- 화면 상단에 저장된 가입연도를 열로 나눈 선수 명단과 인원수를 표시합니다. 가입연도가 없는 선수는 '미입력' 열로 표시하고, 수정 입력칸은 빈칸으로 둡니다. 가입연도 화살표를 처음 누르면 2026년이 입력되고 이후 1년씩 조정됩니다. 기존 가입연도는 그대로 표시하며, 직접 변경한 가입연도만 저장 요청에 포함합니다.
- 미입력 선수의 생년은 빈칸으로 표시됩니다. 빈칸에서 위·아래 화살표(버튼 또는 키보드)를 처음 누르면 1985년으로 시작하고, 이후에는 1년씩 증감합니다. 수정한 셀은 파란색 테두리로 표시됩니다. 표 맨 아래의 저장 버튼을 누르면 검색으로 숨겨진 행을 포함하여 변경한 선수와 연도 항목만 저장하고, 저장 확인 결과는 팝업으로 표시합니다. 생년과 가입연도는 1900년부터 올해까지 입력할 수 있고, 빈칸으로 저장하면 삭제됩니다.
- REQUEST_SHEET_ID의 비공개 스프레드시트에 PLAYER_BIRTH_YEARS 시트가 자동 생성됩니다. 회원명, 생년, 수정 시각, 가입연도를 저장합니다. 기존 생년 시트는 가입연도 열을 추가해 유지합니다. 스프레드시트의 공유 범위는 관리자에게만 허용해야 합니다.
- 조회 및 저장은 기존 관리자 인증을 통과해야 합니다. 생년과 가입연도는 공개 GitHub CSV·신청 이력·브라우저 저장소에 저장하지 않으며 공개 선수 카드에도 표시하지 않습니다. 로그아웃하면 관리자 화면의 데이터도 지워집니다.
- 화면과 API를 함께 배포해야 사용할 수 있습니다. 추가 Script Properties 설정은 필요하지 않습니다.

## 주말 훈련(Beta)

- `주말 훈련(Beta)`에서 관리자가 주를 이동하고 토·일을 선택해 **선택한 날짜 개설**을 누릅니다. 회원에게는 개설된 날짜만 버튼으로 표시됩니다. 미개설 날짜의 신청·편성·출석 저장은 서버에서 차단하며 기존 날짜 재개설은 신청을 초기화하지 않습니다. 관리자 로그인 후 날짜별 **추천 조합**을 누르면 그 아래에 운영진용 초안을 표시합니다. **편성 공개**를 눌러야 회원들에게 보입니다. 활성 화면은 30초마다 갱신하며 멤버 선택 중에는 갱신하지 않습니다.
- 추천·배 추가·삭제·멤버 교체·고정·랜덤 배정은 `static/training-plan.js`로 화면 메모리에서 처리하며 클릭마다 DB를 갱신하지 않습니다. 쿼드는 COX 포함 5개, 더블은 2개, 싱글은 1개 슬롯을 한 줄에 표시합니다. 배별 **랜덤 배정**은 다른 배의 배정자를 제외하고 해당 배의 고정 슬롯은 유지합니다. 인원이 모자라면 남은 슬롯은 비워 둡니다. **삭제**는 배와 그 배의 고정을 제거하고 배정자를 대기로 돌려놓습니다.
- 초안의 이름을 누르면 참석자 버튼에서 교체할 수 있습니다. 이미 다른 좌석에 배정된 사람은 두 좌석을 교환하고, 직접 변경한 이름에는 파란 테두리를 표시합니다. 이름을 650ms 길게 누르거나 멤버 선택 안의 고정 버튼으로 고정/해제할 수 있습니다. **추천 배정**은 고정된 사람의 배와 좌석을 유지합니다. 보유 보트 수를 넘거나 빈 좌석이 있는 편성은 공개할 수 없습니다.
- 하단 **임시저장**은 현재 날짜의 조합을 비공개 시트에 한 번 저장하며, 빈 슬롯도 저장할 수 있습니다. **편성 공개**는 현재 화면 조합을 한 번 검증·저장해 회원에게 공개합니다. 조회·저장에는 관리자 인증을 요구하고 공개 API에는 초안을 포함하지 않습니다. 기존 공개 편성은 다음 공개까지 유지하며, 이미 공개한 편성도 **편성 수정**으로 수정할 수 있습니다. 서버는 보트 종류·상한·좌석·참석 여부·중복을 검증하고 이름은 저장된 회원 이름으로 정규화합니다.
- 미저장 조합은 자동 새로고침·탭 전환 중에도 유지하고 페이지 이탈 시 경고합니다. 임시저장 후에는 다시 접속해 복원할 수 있습니다. 편집 중 다른 운영진이나 신청자가 변경하면 이전 버전으로 덮어쓰지 않고, **최신 명단 반영**으로 검토한 뒤 저장하도록 합니다.
- 기존 비공개 스프레드시트의 `WEEKEND_TRAINING` 시트에 저장합니다. GitHub CSV에 저장하지 않습니다. 이름·신청 상태·편성·출석은 공개 페이지 API로 조회 가능합니다. 선수의 생년 등 비공개 정보는 사용하지 않습니다.
- 같은 이름의 수정은 최초 신청 브라우저에 저장한 무작위 수정키로 보호합니다. 회원 신원을 확인하는 로그인 방식은 아닙니다. 서버에는 SHA-256 해시만 저장하며 수정키와 해시는 응답에서 제외합니다. 브라우저 저장소를 지우거나 기기를 바꾸면 기존 신청을 수정할 수 없습니다.
- 숙련도 자기 선택은 없으며 기존 비공개 선수 정보의 가입연도로 연차를 산정합니다(훈련 연도 − 가입연도 + 1). 추천 때 최신 가입연도를 다시 조회해 쿼드에 연차를 순차 분산합니다. 가입연도 미등록·훈련 연도보다 미래인 경우 추정하지 않고 운영진 확인으로 표시합니다. 가입연도와 생년 원본은 공개 API 응답에서 제외합니다.
- 신청은 **이름 → 참가 여부 → 코멘트** 순서입니다. 날짜 버튼은 `10/24(토)` 형식으로 표시하며 날짜끼리만 복수 선택할 수 있습니다. 불참·미정을 선택하면 나머지 옵션은 비활성화되고, 선택한 항목을 다시 누르면 해제됩니다. 선택하지 않은 개설 날짜는 불참으로 저장합니다. 응답·코멘트를 한 요청으로 검증한 뒤 저장하고, 성공하면 완료 팝업을 표시합니다. 코멘트(최대 1000자)는 참가 명단에 표시합니다. 신청 버튼은 **참가 신청**으로 표시하며 불필요한 제목·설명 문구는 제거했습니다.
- 화면의 추천은 유타쿼드 4대(각 조수 4명 + COX 1명), 더블 2대, 싱글 1대를 상한으로 최대 인원을 먼저 배정하며 같은 인원이면 쿼드를 우선합니다. 가입연도로 인원을 분산하고 등록된 COX·소형 보트 가능자를 해당 좌석에 우선 배정합니다. 가능 정보가 없더라도 연차순으로 추천 초안을 채우며 운영진이 검토 후 공개합니다. 시간·희망 보트는 배정 조건으로 사용하지 않습니다. 좌석을 초과하는 인원은 대기로 표시합니다.
- 참가 명단은 날짜 선택 없이 해당 주의 개설 날짜별 참석 표를 위에서 아래로 나열하고, 마지막에 불참/미정 표를 표시합니다. 한 날짜라도 참석하는 회원은 해당 날짜 표에만 표시하고 불참/미정 표에는 중복 표시하지 않습니다. 불참/미정 표는 이름당 한 번 표시하며 미정 응답을 우선합니다. 현재 주가 미개설이면 다음 개설 주(없으면 최근 개설 주)를 표시합니다.
- 모든 표는 관리자 선수 정보의 가입연도 열 구성을 프리셋으로 공유하며 참가자가 없는 열도 유지합니다. `trainingRoster` 공개 API는 프리셋 가입연도 목록과 개설된 훈련의 공개 명단만 반환하고, 미신청 회원의 이름·생년·수정키는 반환하지 않습니다. 선수 정보 표와 같은 열 너비·행 간격·일반 굵기의 이름을 사용합니다. 제목은 연차 없이 `2023년` 형식이며, 미입력 열은 마지막에 배치하고 열 안의 이름은 가나다순입니다. 참석은 검정, 불참은 빨강, 미정은 회색으로 표시합니다. 코멘트는 이름 아래에 표시합니다. 운영진 추천 편성 버튼은 날짜별 표 아래에 표시합니다.
- 출석 상태는 미확인·출석·불참으로 기록합니다. 출석 변경은 편성을 자동 조정하지 않습니다. 편성 후 신청이 바뀌면 변경 안내를 표시합니다. 추천 및 출석 저장은 관리자 인증과 버전 검사를 거칩니다.
- `apps-script/Training.gs`를 포함해 프런트엔드와 Apps Script를 함께 배포해야 합니다. 기존 자동 배포가 `apps-script/` 전체를 업로드합니다. 추가 Script Properties는 없습니다.

## 대회 조 편성(Beta)

- 새 메뉴에서 연도와 대회를 추가합니다. 기존 대회 목록을 고르거나 새 대회명을 입력할 수 있습니다. 생성한 편성은 비공개 `COMPETITION_LINEUPS` 시트에 저장하며 기존 대회 기록 CSV를 수정하지 않습니다.
- 운영진은 선수 정보의 가입연도별 표에서 참가자를 선택하고 **참가자 저장**을 누릅니다. 참가자가 확정되어야 종목·나이대·팀명으로 조를 추가할 수 있습니다. 활동 선수만 선택하며 이름 아래에 해당 대회 연도의 나이를 표시합니다.
- 나이는 사용자 확인에 따라 `대회 연도 − 출생연도`로 계산합니다. 생일 일자는 사용하지 않습니다. `160~200`은 160세 이상·200세 미만(정수 160~199), `160미만`은 159세 이하, `200이상`은 200세 이상으로 처리합니다. 일반부는 합계 범위 제한이 없습니다. 해석할 수 없는 종목/나이대는 추정하지 않고 선택 목록에서 제외합니다.
- 종목의 인원수대로 COX·출전 슬롯과 **후보 2개(선택)**를 만듭니다. 콕스와 후보는 합계 나이에 포함하지 않습니다. 선수 생년이 없으면 출전 선수로 최종 확정할 수 없습니다. 후보는 선택하지 않아도 됩니다. 슬롯 이름 아래에 만 나이, 조 아래에 합계를 표시합니다.
- 슬롯 선택·비우기·고정·조 추가/삭제·배정은 화면 메모리에서 처리합니다. **랜덤 배정**은 해당 조의 출전 슬롯만 채우며, 다른 조에 같은 종목으로 배정된 선수와 모든 선택된 후보를 제외합니다. 다른 종목에는 같은 선수를 배정할 수 있습니다. **추천 조합**은 미리 추가한 조들 안에서만 나이 조건을 충족하는 조합을 탐색합니다. 고정과 후보를 유지하며 모든 조를 만족하는 결과를 찾지 못하면 기존 편성을 보존합니다.
- `static/race-lineup-plan.js`와 `apps-script/RaceLineupPlan.gs`는 동일한 계산·검증 모듈입니다. 합계 범위를 만족하는 부분집합을 계산하고, 여러 조는 제한된 재탐색으로 편성합니다. 조건에 맞는 조합을 찾지 못했다고 해서 수학적으로 불가능함을 단정하지 않습니다.
- **임시저장**은 빈 슬롯을 포함한 비공개 초안을 저장합니다. **최종 확정**은 저장된 최신 선수 정보로 좌석 수·참가자·종목 내 중복·콕스 제외 합계 나이를 서버에서 다시 검증한 뒤 회원용 확정본을 만듭니다. 이후 초안을 수정해도 다음 최종 확정까지 기존 확정본을 유지합니다. 공개 API는 확정본의 이름·나이만 반환하며 전체 선수의 생년/가입연도·초안·미확정 참가 명단은 반환하지 않습니다.
- 편성 저장·확정에는 관리자 인증과 버전 검사를 적용합니다. 로그아웃 시 선수 정보와 편집 내용을 지우며 늦게 도착한 관리자 응답도 반영하지 않습니다. Apps Script의 `RaceLineup.gs`, `RaceLineupPlan.gs` 및 `Code.gs`와 웹 파일을 함께 배포해야 합니다. 추가 Script Properties는 없습니다.

python -m http.server 8000

## 검증 시나리오

Android 앱은 사이트 메뉴의 **Android APK 다운로드**에서 설치할 수 있습니다. 배포 파일은 `downloads/samsung-rowing-club.apk`, 버전·SHA-256은 `downloads/android-release.json`입니다. 네이티브 프로젝트와 서명키 백업·재빌드 절차는 [Android 앱 문서](android/README.md)에 정리했습니다. 사이트 내용은 온라인으로 반영되며, 앱 자체를 업데이트할 때는 같은 서명키와 더 높은 versionCode를 사용합니다.

1. 새 회원의 기록·사진을 신청하고 관리자에서 승인합니다. records.csv의 GitHub commit과 리더보드 반영을 확인합니다.
   여러 에르고 요청을 선택해 일괄승인하고 선택된 기록만 한 번에 추가되는지도 확인합니다.
2. 회원 상세에서 삭제 요청을 만들고 승인합니다. 해당 record_id 한 건만 사라지는지 확인합니다.
3. 종목을 추가·이름 수정하고, 기록이 없는 종목만 삭제되는지 확인합니다.
4. 사진이 있는 승인 기록의 시간 숫자를 눌러 GitHub 저장소 사진 모달이 열리는지 모바일/데스크톱에서 확인합니다.
5. 대회 기록을 신청·승인한 뒤 출석 및 메달 TOP 5와 클럽 총계, 연도별 표가 함께 갱신되는지 확인합니다.
6. 관리자에서 대회를 추가·이름 수정하고, 참가 이력이 없는 대회만 삭제되는지 확인합니다.
